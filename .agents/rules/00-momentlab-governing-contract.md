# Governing contract

- Read `MOMENTLAB-BUILD-PROMPT.md`, `UI-IMPLEMENTATION-CONTRACT.md`, and `momentlab-reference-pack/README.md` before product implementation.
- Treat `UI-IMPLEMENTATION-CONTRACT.md` as the route, component, state, and visual acceptance authority.
- Preserve existing compatible work and keep the repository runnable after every bounded change.
- Use typed contracts, deterministic fixtures, and explicit finite states. Do not scatter demo values through components.
- Never claim a command, test, integration, deployment, metric, screenshot comparison, or result succeeded without captured reproducible evidence.
- Ask only when credentials, billing, an irreversible action, or a genuinely material product choice blocks safe progress.
- Maintain `docs/progress.md`, `docs/decisions.md`, and `docs/compliance-matrix.md` as implementation changes.
